How it works

Two guarantees, enforced at the boundary

OpenShell governs what agents can do in two ways: it instruments the kernel to enforce policy on every file access, system call, and network connection at runtime, and it uses formal verification to check what a policy change would allow before it is applied.

Read files Install packages Call APIs Use credentials No unrestricted network No leaked secrets
System architecture

Control plane, data plane, and the boundary between them

User interfaces talk to the gateway. The gateway places each sandbox through a compute driver and formally verifies policy changes with the prover. Inside the runtime, a trusted supervisor governs an untrusted agent whose only network path is a mediated channel.
